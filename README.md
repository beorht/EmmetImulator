# Emmet · Тетрадь

Тренажёр [Emmet](https://emmet.io/) и вёрстки на HTML. Занятие состоит из двух частей:

1. **Emmet.** Каждый студент получает свой случайный набор из 10 самостоятельных практических работ из банка в 30 работ. Слева — образец: HTML, который должен получиться, и его вид в браузере. Справа — тетрадь ученика: редактор в клетку, где нужно самому подобрать Emmet-сокращение, развернуть его и сразу получить проверку. Подсказок и готовых решений нет.
2. **Контейнеры.** Короткая теория «id, class и контейнеры» (`div`, `header`, `nav`, `main`, `footer`), затем 10 заданий, одинаковых для всех. HTML можно писать руками. Код ответа не показывается: слева сверху — как код ученика выглядит в браузере, снизу — как должен выглядеть, чистый HTML без стилей. Переключатель «Схема» рисует обе страницы коробками с метками тегов, id и class.

Каждый студент входит по личному ID. Его попытки и решения собираются на сервере, а преподаватель видит прогресс группы в панели `/admin`.

Проект сделан по плану из [`docs/emmet_learning_project_plan.md`](docs/emmet_learning_project_plan.md).

## Возможности

- **Образец результата.** Итоговый HTML с подсветкой и его вид в браузере. Сокращение не показывается — его ученик подбирает сам.
- **Редактор-тетрадь** на CodeMirror 6: подсветка синтаксиса, нумерация строк, фон в клетку, `Tab` разворачивает сокращение Emmet.
- **Структурная проверка.** Сравнивается дерево DOM, а не текст: отступы, переносы и порядок атрибутов не важны. Сообщения об ошибках конкретные: «Внутри `<ul>` должно быть 3 × `<li>`, сейчас 2».
- **Только через Emmet.** HTML, набранный или вставленный руками, не засчитывается: такой фрагмент подсвечивается волнистой линией.
- **Безопасный предпросмотр** кода ученика в изолированном `iframe`.
- **Раздел «Контейнеры»:** теория по презентации и 10 заданий только на HTML, без CSS. Образец — чистый HTML, как в браузере. На переключателе «Схема» — коробки как в презентации: `header` — синяя коробка, `nav` — оранжевая, `main` — зелёная, `footer` — фиолетовая, `div` — пунктир, у тегов с `id` и `class` — метки `h1#logo`, `p.card`.
- **Банк из 30 работ** (7 лёгких, 4 средних, 19 сложных) и **персональные наборы**: каждому студенту случайно выдаются 10 работ — 3 лёгкие, 2 средние и 5 сложных. У соседей по парте наборы разные. Без подсказок.
- **Вход по ID и статистика.** У каждого студента свой ключ. Прогресс сохраняется на сервере и восстанавливается при следующем входе с любого компьютера.
- **Панель преподавателя:** матрица «студент × работа», попытки до решения, время, случаи ручного ввода HTML, код каждого решения, выгрузка в Excel и печать карточек с ключами.
- **Доступность:** управление с клавиатуры, живой регион для сообщений, поддержка `prefers-reduced-motion`.

## Быстрый старт

Нужен Node.js 20.19+ или 22.12+ (требование Vite 8).

```bash
npm install
npm run dev       # сервер разработки → http://localhost:5173
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Сервер разработки с горячей перезагрузкой и API → http://localhost:5173 |
| `npm run keys` | Выдаёт ключи по списку группы (см. ниже) |
| `npm run build` | Собирает сайт в `dist/` |
| `npm start` | Сервер для занятия: сайт из `dist/` и API в локальной сети → порт 3000 |
| `npm run preview` | Собранный `dist/` с API → http://localhost:4173 |
| `npm test` | Тесты проверки ответов, сервера и расчётов панели (Vitest) |

Статистика хранится на сервере, поэтому статического хостинга (GitHub Pages и т. п.) теперь недостаточно: нужен Node.js.

## Занятие: аккаунты и статистика

### 1. Ключи для группы

Список группы лежит в `server/data/roster.txt`, по одному ФИО в строке. Команда

```bash
npm run keys
```

выдаёт каждому студенту ключ вида `stWeb-###`, где `###` — три случайные цифры (например `stWeb-407`), и создаёт ключ преподавателя вида `ADM-XXXX-XXXX`. Ключи не повторяются. При вводе регистр букв, пробелы и дефис не важны: `stweb407` тоже подойдёт.

Повторный запуск не меняет уже выданные ключи: так добавляют новых студентов, дописав их в `roster.txt`. Сервер перезапускать не нужно.

Результат:
- `server/data/accounts.json` — ключи для сервера;
- `server/data/keys.csv` — список «ФИО; ID» для Excel;
- `server/data/keys.md` — тот же список вместе с ключом преподавателя.

Ключи также видны в панели преподавателя (кнопка «Ключи»). Оттуда же печатаются карточки для раздачи, по две в ряд, с линиями отреза.

### 2. Запуск на занятии

```bash
npm run build
npm start              # или PORT=8080 npm start
```

Сервер напечатает адреса: «для студентов» — адрес компьютера преподавателя в локальной сети (например `http://192.168.1.20:3000`), и панель преподавателя `http://localhost:3000/admin`. Студенты и преподаватель должны быть в одной сети. Если студенты не могут открыть сайт, проверьте, что брандмауэр пропускает этот порт.

### 3. Что видит студент

Экран входа с полем «Ваш ID». После входа справа вверху видно имя и кнопку «Выйти». Работа продолжается с первой нерешённой работы, решённые отмечены в навигации. Зелёная точка у имени означает, что результаты доходят до сервера. Красная — нет связи: попытки копятся и отправятся сами, когда связь вернётся.

### 4. Панель преподавателя — `/admin`

Вход по ключу преподавателя. Если ввести его на главной странице, откроется панель.

- **Сводка:** кто сейчас в тетради (активность за последние 5 минут), процент решённых работ, среднее число попыток до решения, сколько раз проверка поймала HTML, набранный вручную.
- **Матрица «студент × работа»:** зелёная ячейка — решено (число показывает, с какой попытки), жёлтая — пробовал, но не решил, с рамкой — открыл, но не проверял. Цветная черта над номером работы обозначает сложность. Внизу — сколько студентов решили каждую работу и сколько попыток им понадобилось в среднем. Так видно, какие работы даются группе труднее всего.
- **Карточка студента** (клик по имени): по каждой работе — статус, число попыток с разбивкой по результатам, время от открытия до решения, ручной ввод и **код студента** (принятое решение или последняя попытка). Здесь же можно сбросить статистику студента.
- **Раздел** над матрицей: «Emmet» — 30 работ банка, «Контейнеры» — 10 общих заданий. «Решено» в строке считается по выбранному разделу, сводка сверху — по всем работам.
- **Завершить занятие** — сервер перестаёт принимать решения, у студентов вместо тетради появляется «Занятие окончено», результаты фиксируются на этот момент. «Открыть занятие» возвращает всё обратно, страницы студентов обновятся сами. Состояние хранится в `server/data/session.json` и переживает перезапуск сервера.
- **Excel** — выгрузка таблицы в CSV (открывается в Excel без настройки кодировки).
- Данные обновляются сами каждые 10 секунд.

### Защита от списывания

| Способ списать | Что происходит |
| --- | --- |
| Вставить готовый HTML или сокращение из чат-бота (`Ctrl+V`, меню, средняя кнопка мыши) | Вставка заблокирована, студент видит «Вставка в редактор отключена», попытка записывается в статистику |
| Перетащить текст в редактор | Заблокировано и записано |
| Автонаборщик, ИИ-помощник браузера, диктовка (текст появляется целым куском) | Больше 2 символов за одно нажатие — блокируется как вставка |
| Набрать HTML руками | В разделе Emmet решение не засчитывается («HTML набран вручную»), фрагмент подсвечивается. В разделе «Контейнеры» HTML руками писать можно — это и есть задание |
| Спрятать HTML в текст сокращения: `{<p class="x">…</p>}` | Ошибка сокращения: «В тексте {…} нельзя писать HTML-теги» |
| Набрать HTML руками и «отмыть» его через `Ctrl+Z`, перенос строк `Alt+↑/↓` и т. п. | Чистым считается только то, что пришло из Emmet и из истории правок, всё остальное — ручной ввод. Перенос и дублирование строк отключены |
| Скопировать образец, чтобы отнести его в чат-бот | Образец и предпросмотр не выделяются, копирование на странице отключено |
| Уйти в чат-бот на другой вкладке или в другой программе | Каждый уход дольше 2 с записывается вместе с длительностью. Студент видит предупреждение «Вы были вне тетради 40 с. Преподаватель видит…». Если работа принята в течение 2 минут после ухода дольше 15 с, она помечается «решено сразу после ухода» |

В панели преподавателя работы с признаками списывания помечены красным уголком в ячейке. В колонке «Наруш.» — HTML вручную плюс попытки вставки, в «Вне стр.» — суммарное время вне страницы. В карточке студента по каждой работе видно, что именно произошло.

Чего защита **не** ловит:
- Студент спросил чат-бот на телефоне или посмотрел ответ у соседа и честно набрал сокращение сам. Набор с клавиатуры неотличим от самостоятельного решения. Косвенный признак — очень короткое время решения сложной работы.
- Фото экрана на телефон и вопрос чат-боту с телефона: страницу при этом никто не покидает.
- Подделка результата через инструменты разработчика (см. ниже).

Поэтому отметки в панели — повод присмотреться к работе и посмотреть код студента, а не автоматический приговор.

### Что считается попыткой

Каждая проверка непустого решения: `Tab`, `Ctrl+Enter` или кнопка «Проверить». «Попыток до решения» — номер первой принятой проверки. Повторные проверки после решения считаются в общем числе попыток, но не меняют результат.

### Данные и ограничения

- Всё хранится в `server/data/` в виде JSON (`stats.json` — статистика). Папка исключена из git: в ней ФИО и ключи. Для резервной копии достаточно скопировать её.
- Ключ хранится в браузере до нажатия «Выйти». На общих компьютерах студентам нужно выходить в конце занятия.
- Правильность решения определяет браузер студента, сервер её не перепроверяет. Подкованный студент может подделать результат через инструменты разработчика. Для учебной статистики это приемлемо, для оценок за экзамен — нет.
- Соединение идёт по HTTP без шифрования. Это нормально внутри локальной сети класса, но не для публикации в интернете.

## Как пользоваться

1. Посмотрите на образец слева: какой HTML должен получиться.
2. Прочитайте условие справа и наберите в редакторе Emmet-сокращение, которое даёт такой HTML.
3. Нажмите `Tab`: Emmet развернёт его в HTML, и решение сразу проверится.
4. Если нужно, допишите руками текст или значения атрибутов и проверьте ещё раз.
5. Переходите к следующему заданию стрелками или точками в правом верхнем углу.

### Клавиши в редакторе

| Клавиши | Действие |
| --- | --- |
| `Tab` | Развернуть сокращение слева от курсора и проверить |
| `Ctrl` + `Enter` | Проверить (кнопка «Проверить» делает то же самое) |
| `Ctrl` + `]` / `Ctrl` + `[` | Увеличить / уменьшить отступ |
| `Shift` + `Tab` | Уменьшить отступ |
| `Ctrl` + `Z` / `Ctrl` + `Y` | Отменить / повторить |
| `Esc`, затем `Tab` | Выйти из редактора к следующему элементу страницы |

## Задания

Банк работ Emmet хранится в [`src/data/exercises.json`](src/data/exercises.json), задания на контейнеры — в [`src/data/containers.json`](src/data/containers.json).

Порядок в тетради студента: 10 работ Emmet из личного набора → теория «id, class и контейнеры» → 10 заданий на контейнеры. В навигации теория — круглая точка, задания на контейнеры — зелёные. Нумерация сквозная, только по работам: «11 / 20».

Все работы самостоятельные: у каждой есть только условие, уровень сложности и образец итогового HTML с предпросмотром. Подсказок, демонстраций и готового решения нет.

### Персональный набор

Из банка в 30 работ каждому студенту при первом входе случайно выбираются 10:

| Уровень | В банке | В наборе |
| --- | --- | --- |
| Лёгкая | 7 | 3 |
| Средняя | 4 | 2 |
| Сложная | 19 | 5 |

Набор сохраняется за студентом и не меняется между входами. Внутри набора работы идут от лёгких к сложным. Сервер принимает решения только по работам из своего набора. Наборы выдаются заранее: в панели преподавателя их видно ещё до первого входа студента. В карточке студента есть кнопка «Новый набор» — выдаёт другой случайный набор (статистика по уже решённым работам сохраняется). «Сбросить статистику» набор не меняет.

Количество работ в наборе задаётся в `server/assignment.js` (константа `PLAN`).

### Контейнеры

Одинаковые для всех, идут после теории. Решение — только HTML, без CSS. Вставка, перетаскивание и текст целым куском заблокированы так же, как в разделе Emmet.

| № | Задание | Уровень | Что тренирует |

| 3 | Фрукты | лёгкая | общий `class` у группы |
| 4 | Кнопки магазина | лёгкая | `id` и `class` на одном элементе |

Теория (`src/components/LessonView.js`) повторяет презентацию: id и class (паспорт и форма команды, таблица отличий), `div` как универсальная коробка и вложенность, специальные контейнеры и «почему не просто div». Примеры в теории нарисованы той же схемой коробок, что и в заданиях.

## Как устроена проверка

Проверка проходит по шагам и останавливается на первой найденной проблеме:

1. **Пусто?** Предлагает набрать сокращение.
2. **Не развёрнуто?** Если в коде нет ни одного тега, напоминает нажать `Tab`.
3. **Набрано руками?** (только в разделе Emmet, `mode: "emmet"`) Редактор помечает всё, что ученик напечатал или вставил сам. Если среди этого есть угловые скобки, имена тегов или атрибутов, `=` или кавычки, решение не засчитывается. Руками можно вводить только текст внутри тегов и значения атрибутов. Пометки сохраняются при отмене и повторе, поэтому обойти проверку через `Ctrl+Z` нельзя.
4. **Ошибки разметки:** незакрытые и лишние теги, незакрытые кавычки, оборванный тег.
5. **Структура:** теги, их количество и вложенность сравниваются с эталоном.
6. **Детали:** классы, значения атрибутов и текст. Если структура верна, а детали нет, статус «Почти получилось».

Эталонный HTML не хранится отдельно: он получается развёртыванием `emmetExpression` через тот же пакет `emmet`. Поэтому эталон всегда соответствует сокращению.

## Как добавить задание

Задание на контейнеры добавляется в `src/data/containers.json` с полями `"mode": "html"` и `"section": "containers"`: оно появится у всех студентов в конце раздела. Задание Emmet — в банк `src/data/exercises.json`:

```json
{
  "id": "practice-31",
  "title": "Название",
  "description": "Условие для ученика.",
  "emmetExpression": "section>h2+p",
  "mode": "emmet",
  "validationMode": "structure",
  "difficulty": 1
}
```

Правила:
- `emmetExpression` — эталонное решение. Ученику оно не показывается, из него вычисляются образец и проверка.
- `difficulty`: 1 — простая, 2 — средняя, 3 — сложная.
- Поле `expectedHtml` можно не указывать: оно вычисляется из `emmetExpression`.
- В ожидаемом HTML пустое значение атрибута (`href=""`) означает «атрибут нужен, значение любое».

После добавления запустите `npm test`. Тесты проверят, что каждая работа разворачивается без ошибок и эталон проходит собственную проверку. Тест на количество работ по уровням (7 / 4 / 19) тоже нужно будет обновить. В каждом уровне должно быть не меньше работ, чем требует `PLAN`, иначе сервер не сможет собрать набор.

## Решения по открытым вопросам плана

Ответы на открытые вопросы из раздела 14 плана.

| Вопрос | Решение |
| --- | --- |
| Tab — проверка или отступ? | `Tab` разворачивает сокращение и сразу проверяет результат. Если сокращения нет, только проверяет. Для отступов есть `Ctrl+]` / `Ctrl+[` (или `Tab` при выделении). Кнопка «Проверить» тоже разворачивает однострочное сокращение, потому что на сенсорных клавиатурах нет `Tab`. |
| Где показывать результат кода ученика? | В сворачиваемом предпросмотре внутри панели редактора: `iframe sandbox=""` и CSP, скрипты и обработчики событий вырезаются. |
| Emmet или HTML? | Все задания в режиме `mode: "emmet"`. HTML, набранный руками, отклоняется (см. [проверку](#как-устроена-проверка)). |
| Обучающий материал | Убран: остались только самостоятельные практические работы без подсказок. Вместо анимированной демонстрации — статичный образец результата. |
| Прогресс и аккаунты | Вход по личному ID, статистика на сервере, панель преподавателя (см. [Занятие](#занятие-аккаунты-и-статистика)). |
| Левая визуальная область | Убрана. Сверху панель с логотипом и навигацией, ниже образец и редактор рядом, 50/50. |
| Целевое разрешение | От 1280×720. Проверено на 1366×768 и 1440×900 без прокрутки страницы. На экранах уже 960 px панели встают друг под друга. |
